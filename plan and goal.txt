-- Room search

ON rooms (property_id, listing_status);

-- Room inventory

ON room_units (room_id, status);

-- Reservation lookup
CREATE INDEX idx_reservations_unit_dates
ON reservations (room_unit_id, move_in_date, move_out_date);

-- Tenant reservation history
CREATE INDEX idx_reservations_tenant
ON reservations (tenant_id, created_at);


These are examples of the indexes to create in Laravel migrations, not commands that should be run before creating the tables.
Reservation concurrency protection
This deserves special attention.

Imagine two tenants requesting the same bed space for December 1.

Both requests are initially pending. The landlord approves Tenant A.

Before approving Tenant B, the backend must check whether an approved or confirmed reservation already overlaps.

The approval process should:
1. Begin a database transaction.
2. Lock the selected room unit using SELECT ... FOR UPDATE.
3. Check for overlapping approved or confirmed reservations.
4. If there is a conflict, reject the approval operation.
5. Otherwise, approve the reservation and set its expiration.
6. Record the status change.
7. Commit the transaction.
Pending requests can coexist in the queue. Approved reservations temporarily hold inventory.

This is important for preventing double bookings.

What I recommend we do next
Before coding, I suggest we move to UI/UX design and wireframing.

I want to design these screens:
1. Public homepage – search and featured boarding houses.
2. Search results – filters and property cards.
3. Property details – photos, rooms, amenities and location.
4. Tenant dashboard – reservations and favorites.
5. Landlord dashboard – overview and room availability.
6. Property management – create and edit properties.
7. Room management – individual rooms and bed spaces.
8. Reservation management – incoming requests.
9. Admin dashboard – verification and property moderation.
Once the screens are established, we can map each interface to its database tables and API endpoints.

My suggestion is to design the public tenant marketplace first, because that's the first experience that will attract people to your platform.

We can keep the project name temporary until we develop a modern brand identity.
