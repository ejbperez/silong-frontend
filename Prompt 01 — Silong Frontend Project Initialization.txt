# Project: Silong — Frontend Foundation

Act as a Senior Frontend Engineer and UI/UX Designer. Help me build **Silong**, a modern boarding house and room rental marketplace for students and working professionals in the Philippines.

We are starting this project from scratch. For this initial phase, focus exclusively on the frontend. Do not build the backend or database yet.

## 1. Project Objective

Build a responsive web application where users can:
- Discover boarding houses, private rooms, and bedspaces.
- Search accommodation by location.
- Browse available properties.
- View property details, amenities, pricing, and house rules.
- Eventually submit reservation requests.

The initial launch market is Taguig City, Philippines.

## 2. Technology Stack

Use the following technologies:

- Next.js with App Router.
- TypeScript.
- Mantine UI.
- Phosphor Icons.
- CSS Modules for custom styling where needed.
- ESLint for code quality.

Use stable, compatible package versions and follow current Next.js and Mantine conventions.

## 5. Frontend Architecture

Organize the project using a maintainable structure.

Suggested structure:

- `app/` — routes and layouts.
- `components/` — reusable UI components.
- `features/` — feature-specific components and logic.
- `data/` — temporary mock data.
- `hooks/` — reusable React hooks.
- `lib/` — utilities and configuration.
- `theme/` — Mantine theme and brand configuration.
- `types/` — TypeScript interfaces and types.

Separate reusable components from page-specific components.

Avoid putting the entire application inside one page component.

## 6. Mock Data

Use realistic mock accommodation listings based in Taguig City.

Include examples of:
- Private rooms.
- Shared rooms.
- Bedspaces.

Use reusable TypeScript interfaces for properties, rooms, amenities, and landlords.

Do not hardcode mock property information directly into individual UI components.

Use placeholder images from reliable image sources or local assets. Make sure missing images have graceful fallbacks.

## 7. UI/UX Requirements

- Fully responsive desktop, tablet, and mobile layouts.
- Consistent spacing, typography, colors, and border radius.
- Reusable buttons, cards, inputs, badges, and navigation.
- Accessible labels and semantic HTML.
- Loading, empty, and error states where appropriate.
- Clear visual hierarchy.
- Mobile-friendly search and filter experience.

Use Mantine components where appropriate rather than recreating standard UI elements unnecessarily.

Use Phosphor Icons consistently.

## 8. Development Rules

- Do not implement Laravel API integration yet.
- Do not implement authentication yet.
- Do not implement database functionality.
- Do not implement actual reservations yet.
- Use mock data and frontend-only interactions.
- Do not introduce unnecessary dependencies.
- Keep components reusable and maintainable.
- Follow TypeScript best practices.
- Do not use `any` unless absolutely necessary.

## 9. Development Workflow

Before writing code:

1. Inspect the existing project directory.
2. Present the proposed folder structure.
3. Identify the required packages.
4. Explain the implementation plan.
5. Identify any architectural decisions that should be made before implementation.

Wait for my approval before making significant changes.

After approval, initialize the project and implement the frontend foundation.

Work incrementally. Do not attempt to implement every page in one large component.
